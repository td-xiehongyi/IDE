## 首版方案形成记录（产品流程与顺序已确认，技术细则待阶段设计）

### 产品与实现方向

候选定位：以 Markdown 为核心、可由 Agent 协助维护的本地个人知识库。优先完成日常笔记工作，不再以文件分类整理作为产品主线。新名称尚未决定，暂不更改应用标识或存储目录。

候选路线比较：

- 推荐：在现有 Tauri、React、Rust、SQLite 基础上转型，复用文件访问、监听、索引和操作校验；补齐编辑、链接、历史与知识任务能力。符合独立应用内完成日常工作的目标。
- 继续以原文件整理器为核心叠加聊天：复用表面最多，但日常编辑仍居于次要位置，不符合已确认优先级。
- 从零重写：可以重新组织代码，但会失去已积累的路径校验和操作基础；当前没有足够证据支持承担该成本。

建议一次打开一个知识库，允许切换。前端负责编辑与呈现；Rust 负责文件读写、冲突检查、索引、模型接入与任务执行。原始笔记留在用户目录，SQLite 维护可重建搜索与链接索引；历史快照和回收记录独立于可重建索引，清除索引不得清除恢复数据。具体恢复数据位置和保留策略在实施设计中确定。

### 日常流程与 Agent 流程

日常流程：打开文件夹 → 浏览或搜索笔记 → 即时预览编辑或切换源码 → 自动保存并显示状态 → 通过链接和反向链接导航 → 必要时查看并恢复历史。外部文件变化与未保存编辑相冲突时，不静默覆盖任意一方。

Agent 流程：输入任务并可选限定范围 → 按需搜索、阅读和组合工具 → 回答附可打开的笔记依据，或生成变更提案 → 展示涉及文件、内容差异、路径变化和删除项 → 用户确认 → 复核文件当前版本后执行 → 显示逐项结果和回退入口。

审批默认建议：将一次任务中相互依赖的修改组成一组，允许逐文件查看，但整组确认或取消；要求调整其中一部分时重新生成提案，不以随意取消某个链接更新的方式破坏一致性。确认后文件如已改变，旧提案失效并重新预览。一次确认不能授权后续新增修改。

通用 Agent 的首版基础能力为列目录、搜索、读 Markdown、提出新建/修改/重命名/移动/移入回收区的计划。由这些能力组合出归纳、比较、复习指南、笔记更新和整理任务，不为每种任务写死专用流程。任务可取消、有限制；模型不能直接执行写入，笔记正文不能成为扩大权限的指令。

回退建议按任务恢复，但多文件写入不宣称具备数据库事务式原子性；中断或部分失败要记录实际状态并提供恢复。存在后续编辑或同名占用时，暂停冲突项并让用户选择恢复方式，不覆盖新内容。

### 建设顺序建议

1. 可日常使用的知识库：打开目录、Markdown 即时预览和源码、自动保存、链接与反向链接、搜索、历史与回收恢复。交互有疑义时先做独立预览，再进入正式实现。
2. 基于笔记的 AI：云端和 Ollama 接入、任务范围、正文检索和带依据回答。几百篇先使用进程内/SQLite 索引，不引入独立向量数据库服务；是否加入嵌入检索由真实问题的召回评测决定，中文检索需专项验证。
3. 可维护知识库的 Agent：多步工具使用、整组变更预览、确认后执行、冲突保护与任务回退。最终首版交付包含本阶段，前两步只是建设顺序，不能以只读问答冒充完成用户目标。

联网、图片识别、其他资料格式、同步、手机端和关系图不进入上述首版实现。每阶段单独记录验收和实施授权。

### 验收场景草案

- 导入约几百篇真实 Markdown，编辑并重启后内容一致；中文输入、即时预览和源码切换不破坏正文。性能门槛需结合实际笔记大小与机器测量，不承诺尚未验证的毫秒数。
- 新建链接后出现正确反向链接；重命名和移动后引用仍能定位。重名笔记不得任意选中，失效链接不得假装成功。
- 用真实笔记提出归纳、比较和检索问题，答案依据可打开核对；不存在的信息明确说明不足，避免把检索未命中当成全库不存在的证明。
- 要求新建指南、修改多篇笔记、移动或删除：确认前磁盘不发生 Agent 写入；取消无变更；确认只执行已展示的计划。
- 预览后外部编辑、执行中断、回退时出现后续编辑或路径占用：保留真实操作状态，不静默覆盖，提供可理解的冲突与恢复入口。
- 云端和本地分别走通任务；模型不支持工具调用时明确提示能力限制，不能假装成功执行；密钥不进入笔记目录或日志。
