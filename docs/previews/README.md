# 产品预览与阶段验收

本目录采用“最终愿景 + 阶段验收”双轨管理，避免将未来设计误认为当前已经交付的功能。

| 目录 | 定位 | 能否作为阶段完成证据 |
| --- | --- | --- |
| `final-user-flow/` | 全部阶段完成后的最终用户流程愿景 | 否 |
| `phase-acceptance/` | 从各阶段真实可运行版本中取得的验收资料 | 是 |

## 最终愿景

`final-user-flow/` 中的 7 张 PNG 用于：

- 统一最终交互目标和页面衔接顺序；
- 在阶段五完成后对照设计还原度；
- 帮助讨论尚未实现的功能，但不表示对应功能已经完成。

## 阶段验收

阶段验收资料必须来自对应阶段的真实实现，并记录截图日期、对应提交、已实现功能和未实现功能。

- 截图只展示该阶段已经能够实际操作的功能，不得提前展示未来阶段的可用控件。
- 应用截图统一使用 1200×800 PNG，确保中文正常、页面非空白，且不包含浏览器工具栏或窗口外围。
- 阶段四不为截图增加临时产品入口，以自动化测试报告和测试数据作为主要证据。
- 阶段六以构建、安装、升级和安全检查结果为主，不要求重复产品界面截图。
- 任何概念图、草图或最终愿景图都不能单独作为阶段完成证据。

阶段验收说明和待补资料位于 [`phase-acceptance/`](phase-acceptance/README.md)。
