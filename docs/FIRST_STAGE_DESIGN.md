## 当前基线

- 数据库迁移代码当前到版本 5，使用应用数据目录下的 index.sqlite3；后续必须追加迁移并保留旧操作历史。
- 旧 OperationType 只有 Move 与 Rename；undo_service 通过反向重命名撤销成功操作，并检查原位置、文件身份与父目录。这不是正文版本恢复，也不能直接承担回收与跨卷恢复。
- 现有前端尚无正式 Markdown 编辑器依赖。此次只核对代码与官方文档，没有安装、启动编辑器或验证 Windows 写入行为。

## 编辑器候选

推荐候选为 CodeMirror 6：以原始文本为编辑状态，通过 decorations 做即时预览；源码模式关闭预览装饰，继续使用同一份文本、选区和撤销历史。不要在两种模式间用 Markdown 解析再序列化整篇笔记，以免无意改写原文。

备选 Milkdown 提供 WYSIWYG Markdown 框架，但需额外验证解析/序列化对原有 Markdown 格式的保留。当前原文保存和源码切换优先，因此先验证 CodeMirror 候选，不宣布选型已通过。

即时预览需要自己实现并验证标记隐藏与光标交互，并非安装 CodeMirror 即获得完整 Obsidian 体验。优先覆盖标题、强调、列表、引用、代码块、链接与表格；选区所在语法显示原始标记，中文输入组合期间不改动相关装饰。模式切换不触发正文变更或额外保存。

已确认（D21）：数学公式和 Mermaid 图表的专用渲染放到后续。首版以可编辑源码呈现公式，以普通代码块呈现 Mermaid；不安装相关渲染依赖，不执行图表生成。即时预览、源码模式切换和保存都必须保留这些原文，不因暂不支持渲染而删除或重写。后续渲染沿用笔记内的源码，不要求迁移到专有存储格式。

官方资料：[CodeMirror 系统说明](https://codemirror.net/docs/guide/)、[装饰示例](https://codemirror.net/examples/decoration/)、[API 与 IME 状态](https://codemirror.net/docs/ref/)、[Milkdown 入门](https://milkdown.dev/docs/guide/getting-started)。以上用于能力调研，不证明本项目集成质量。

## 自动保存候选流程

默认建议停止输入 1 秒后保存；中文输入组合结束后开始计时。Ctrl+S 立即请求保存。每篇笔记只允许一个保存请求进行中，后续输入合并到下一次请求，防止乱序响应覆盖新内容。

状态区分已保存、编辑中、保存中、保存失败和外部冲突。基线包含磁盘内容版本；保存中继续输入，旧请求成功不能把新输入标成已保存。失败保留内容；切库、关页和关闭应用等待保存结果，失败时让用户处理，不直接丢弃。

外部修改且编辑器无本地变化时刷新内容；存在本地变化时暂停该笔记自动保存，展示本地/磁盘差异，允许保留副本或明确选择后重新保存。Windows 实际替换协议、草稿恢复与关闭事件集成待验证，不以先检查再写入的简单顺序宣称消除了并发竞态。

## 链接候选规则

首版识别正文中的 [[笔记]]、[[文件夹/笔记]]、[[笔记|显示名]]，以及本地 Markdown 链接；代码块和行内代码中的相同文本不是引用。不默认支持块引用或全部 Obsidian 扩展语法。

已确认（D20）：仅名称的 wiki 链接在全库唯一时直接定位，重名则显示候选并让用户选择，不自动绑定任意文件；选择后保存含目录的链接，改名/移动同步更新相关引用。路径型 wiki 链接相对知识库根目录、普通 Markdown 相对链接相对当前笔记仍为技术建议，尚未等同于全部解析细则已确认。

断链保留原始文字并显示未找到，不因展示或检索而自动创建文件。重命名/移动先计算解析后确实指向目标的引用，并形成整组变更；歧义引用不能按字符串相同批量替换。标题锚点、特殊字符转义、大小写与重解析点处理需要在规则确认后补全。

## 恢复与数据设计

保持正式 Markdown 在知识库中；应用数据区独立保存内容快照与操作记录，搜索索引可重建但不能清掉恢复数据。保存前版本与成功结果需能在中断后核对，不能只保留路径历史。

历史版本保留策略已确认：默认长期保留，由用户手动清理，不自动按时间或空间淘汰。历史保存节奏仍需设计；长期保留不等于每次键盘输入都生成一个独立版本。

清理交互建议：先列出选择的笔记/版本、可释放空间，以及将失去的恢复能力；确认后才清理。若版本被任务回退引用，必须明确显示关联任务，不能清理后仍把该任务显示为可完整回退。回收内容单独列出，不能混在普通历史清理中被隐式删除。永久清空回收区尚未获得本次回答的授权。

默认不因达到空间阈值静默清理。空间不足时明确提示；若无法建立写入所需的恢复记录，则保留编辑内容并阻止该次磁盘写入，不能静默取消恢复保护。提示阈值与快照去重策略属于后续实现细则。

回收必须先验证恢复内容已持久保存，再处理正式位置；因知识库与应用数据可能位于不同卷，不能套用旧 fs::rename 撤销实现。实际协议需要单独设计并在隔离副本验证；当前未启用删除能力。

## 保存与恢复具体方案（保存与检查点已确认；协议仍待验证）

### 保存节奏与界面状态

- 手动输入结束 1 秒后自动保存；中文输入组合结束后开始计时。Ctrl+S、切换笔记、关闭标签页、切库和正常关闭应用触发待保存内容提交。
- 每篇笔记串行保存；同一知识库内的批量变更与涉及笔记的保存互斥。收到旧请求成功响应时，若已有新输入，仍显示待保存并提交最新内容。
- 没有内容变化不写文件、不生成版本。保存指示区分待保存、保存中、已保存、保存失败、外部冲突和恢复待处理；历史持久化失败不能显示“已保存且可恢复”。
- 保存失败保留编辑缓冲区，提供重试和保留副本入口；关闭/切库受阻时可取消该操作，不默认丢弃。保留副本也要确认目标并采用不覆盖创建。
- 正常关闭不丢未保存内容是目标；强制终止、断电或尚未落盘的最后输入无法保证恢复，不宣传零丢失。异常重启只恢复已持久化内容，不把崩溃前输入全部恢复作为未经验证的承诺。

### 历史粒度（D22 已确认）

正文停止输入 1 秒后保存；永久历史不随每次自动保存增长。切换笔记、关闭笔记和正常退出时，对相对上一个检查点发生变化的内容保存历史；持续编辑每 5 分钟补一次有变化的检查点。首次改写前保留原文，Agent 修改、删除和恢复前独立保留必要版本。

检查点仅记录已经成功保存的版本；保存失败或外部冲突时不把编辑缓冲当作已完成版本。相同内容不重复留版本。未到检查点的中间自动保存状态不承诺可永久恢复；每次写入所需的临时恢复数据，在结果核对完成且不被历史或任务引用后才释放，这不是自动删除用户历史。

历史由用户手动清理，界面可按日期折叠。编辑会话内撤销与长期历史独立。此规则替代先前每次自动保存均保留永久版本的候选，采用原因是减少空间增长。

Agent 任务和人工改名/移动、删除、恢复形成独立操作记录；恢复旧版本产生新当前版本，不抹去较新历史。多文件操作仅对实际成功项提供恢复。

### 外部修改与恢复选择

| 情况 | 默认处理 |
| --- | --- |
| 外部内容变化，编辑器没有本地未保存内容 | 重新读取并提示已刷新；若正执行写入，等写入状态核对后处理 |
| 外部内容变化，编辑器有本地未保存内容 | 暂停该笔记自动保存，展示两份内容，默认建议另存本地副本；不自动合并或覆盖 |
| 用户选择采用磁盘内容 | 明确告知会放弃当前编辑缓冲；能持久保留本地副本时先保留，失败则不悄悄丢弃 |
| 用户选择用本地内容更新原文件 | 重新读取磁盘基线并展示差异，经明确操作后保存；再次变化则继续提示冲突 |
| 回退时存在后续修改或同名占用 | 默认建议恢复为新副本，或取消；用户选择替换当前内容时重新预览并保存当前版本 |
| 外部删除或移动当前笔记 | 提示文件状态变化，不因自动保存重新创建同名文件；允许明确另存 |

外部变更只能记录应用实际观察到的版本，不保证捕获外部编辑器的所有中间状态。基础编辑撤销（当前编辑会话）与持久历史恢复分开呈现。

### 存储与执行顺序

建议按知识库隔离，将快照字节与恢复元数据放在系统应用数据区，使用现有 SQLite 追加表管理引用和执行状态。索引重建只删除派生索引。快照不进入 Agent 搜索，应用关闭后仍可恢复，密钥和模型上下文不进入快照。

每次维护的设计顺序为：锁定应用内部相关笔记 → 校验路径及文件身份/内容 → 持久记录原文和待执行状态 → 准备新内容 → 再核对并执行写入 → 记录真实结果 → 更新编辑器版本与索引。应用内部锁不能阻止其他编辑器；“两次检查”也不是原子比较并写入，不以此宣称已完全消除并发覆盖。

Windows 写入候选为同目录临时文件与 ReplaceFileW，并保留可核对的被替换版本；但该 API 的共享访问、备份位置和失败后文件状态需要专项验证。不能用普通跨卷 rename 替代，也不能在 API 返回失败时假定磁盘没变化。执行协议尚未锁定，在验证前不开放正式保存能力。

回收采用先持久复制原始内容并核验，再在确认文件未变化后移除正式位置的受控流程，解决知识库和应用数据位于不同卷的情况。执行日志需区分恢复副本已准备、正式文件已移除、结果已记录；中断后检查实际文件状态，不根据日志猜测或盲目重试删除。用户批准删除仍不等于批准移除更新后的版本，检查和移除之间的竞态须与写入协议一起验证。

恢复时目标为空采用不覆盖创建，目标已占用则进入冲突流程。空间不足或恢复数据持久化失败阻止会削弱恢复能力的操作，并保留可用内容。长期保留期间不进行自动过期清理。

## 本轮阶段设计收敛（2026-09-06，待实现授权）

本节把第一阶段从“候选流程”收敛为可交接的实现边界。它仍然是设计，不代表已经修改应用代码、安装编辑器依赖或通过 Windows 文件故障验证。

### 第一阶段目标与停止范围

第一阶段完成后，用户可以选择一个本地文件夹，在应用中浏览 Markdown、打开多篇笔记、即时预览或编辑源码、自动保存、搜索和使用笔记链接；保存失败、外部修改和历史恢复都有可理解的状态。原始 Markdown 文件仍是正式内容，应用数据区只保存索引、版本快照和恢复元数据。

本阶段不接入云端 AI、Ollama、Agent 工具调用、联网搜索、图片识别、公式渲染、Mermaid 渲染、非 Markdown 内容、同步和移动端。Agent 侧栏可以继续作为 UI 占位，但不能读取或写入真实文件。

### 文件边界与身份

- 用户选择的目录经过现有 `path_policy` 规范化后成为当前知识库根目录；所有读写命令必须同时接收根目录和相对路径，并再次验证路径仍在根目录内。
- 只允许普通 `.md` 文件进入编辑流程；目录、符号链接、非 Markdown 文件和根目录外路径返回明确错误，不自动复制或创建目标。
- 打开文件时读取 UTF-8 字节，返回相对路径、正文、大小、修改时间、文件身份和内容哈希作为编辑基线。哈希用于保存前的乐观并发检查，不能只依赖修改时间。
- 前端不把绝对路径当作笔记 ID；UI 使用“根目录 + 相对路径”，Rust 层使用规范化路径和现有文件身份检查。

### 保存状态机

每个打开的笔记独立维护以下状态：`loading`、`clean`、`dirty`、`saving`、`save_failed`、`external_changed`、`restoring`。正文状态包含 `base_snapshot`、`draft_text` 和递增的 `edit_generation`。

停止输入 1 秒后发起保存；中文输入组合期间不计时。保存请求携带打开时或上次成功保存后的内容哈希与 `edit_generation`。同一笔记只允许一个请求进行中；旧请求返回成功时，如果 generation 已变化，界面仍显示待保存并继续提交最新正文。

保存命令在 Rust 侧重新读取当前文件并比较基线哈希；一致时使用同目录临时文件和经过验证的替换流程写入，不一致时返回冲突而不覆盖。成功后再持久记录版本和更新索引；任何一步失败都保留前端正文并显示失败原因，不能显示“已保存”。

### 版本与恢复数据

新增迁移建议建立按知识库和相对路径隔离的 `document_versions` 表，至少保存版本 ID、根目录、相对路径、正文快照、内容哈希、文件身份、大小、创建时间、版本原因和来源（人工保存、切换/关闭检查点、恢复、Agent/操作任务）。快照与 `file_entries` 的可重建索引分开，索引重建不得删除版本。

永久历史规则采用 D22：首次改写前保存原文；切换笔记、关闭标签、正常退出和持续编辑每 5 分钟只为有变化且已经成功保存的内容创建检查点；相同哈希不重复留版本。恢复旧版本时先展示当前与目标差异，确认后将恢复结果作为新当前版本，不删除较新历史。

历史清理为用户显式操作：先显示版本数量、可释放的独占空间和受影响的回退记录，再确认删除。普通历史清理不包含当前文件、回收内容、执行中任务或未解决恢复任务；本阶段先实现历史查看、差异预览和单版本恢复，清理可在同一阶段后半段接入。

### 交互流程

1. **打开知识库**：选择目录 → 扫描/恢复最近索引 → 展示目录树 → 仅在用户打开笔记时读取正文。
2. **打开笔记**：显示加载状态 → 读取正文与基线 → 进入即时预览；读取失败保留目录并显示可重试错误。
3. **编辑与保存**：编辑器显示 `dirty` → 停止输入 1 秒 → 显示保存中 → 成功显示已保存；失败提供重试和“另存副本”，不丢当前正文。
4. **切换、关闭或切库**：先提交待保存内容；成功后生成必要检查点；冲突或失败时暂停动作，让用户选择重试、另存或取消。
5. **外部修改**：无本地变化时刷新并提示；有本地变化时进入冲突视图，展示本地草稿与磁盘正文，用户选择保留副本、采用磁盘内容或重新预览后覆盖。
6. **历史恢复**：历史入口只针对当前笔记；选择版本后查看差异和完整内容，明确确认后恢复为新版本；当前文件已被后续修改或目标被占用时暂停恢复。

### 第一阶段候选命令边界

前端通过 `src/lib/documents-api.ts` 调用以下 Tauri 命令；名称和字段在实现前可因验证调整，但不得绕过根目录、基线哈希和状态返回：

- `read_markdown_document(root_path, relative_path) -> DocumentSnapshot`
- `save_markdown_document(request) -> SaveResult`
- `get_document_history(root_path, relative_path, limit, offset) -> DocumentVersionSummary[]`
- `read_document_version(version_id) -> DocumentVersion`
- `restore_document_version(request) -> RestoreResult`
- `clear_document_history(request) -> ClearHistoryResult`

文件监听继续通过事件通知当前根目录变化；新增文档事件至少包含根目录、相对路径、磁盘哈希和变化类型。前端收到事件后只标记对应标签为外部变化，不自动覆盖编辑缓冲。

### 实现任务与验证门槛

实现顺序固定为：编辑器真实样本验证 → 文档读取命令 → 单笔记保存队列 → 版本快照与恢复 → 外部冲突 → 搜索/链接接入 → 关闭与重启恢复。每一步都先有自动测试，再做真实 Windows 隔离目录验证。

必须通过的最小场景包括：中文输入组合不丢字；源码与即时预览往返不改写未编辑内容；停止输入后只保存最新正文；保存失败保留正文；外部修改不被覆盖；重启后能打开上次知识库和历史；恢复前可查看差异且恢复结果生成新版本；索引重建不删除版本。任一故障场景未验证时，不开放对应写入或删除能力。

### 手动清理流程

选择历史范围 → 显示版本数量、实际可释放的独占空间和受影响回退任务 → 确认 → 删除相应引用及确实无人引用的快照 → 更新可恢复状态。去重快照仍被其他历史引用时不删除，不能按所有被选版本的字节总和虚报可释放空间。

普通历史清理不包含当前文件、回收内容、执行中记录或未解决恢复任务。回收区永久清空仍不在当前已确认功能范围。清理是用户显式动作，Agent 无此工具。

### 协议验证门槛

执行方：未来获授权的实现/验证工作；本轮未安装依赖或执行文件故障实验。最晚在正式编辑保存与删除接入前完成：两个进程并发编辑/替换、文件占用、权限失败、磁盘空间不足、不同卷回收、各日志断点中断、重启恢复。仅在检查后没有任何原文被丢失且每项状态与磁盘一致时才接入；无结果则保持待验证，不退化为不受保护的原地覆盖或永久删除。
