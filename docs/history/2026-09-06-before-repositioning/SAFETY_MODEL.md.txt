## 文档地位

本文档是文件扫描、持久化、写操作、知识索引、引用和 Agent 权限的规范性来源。产品范围见[产品需求文档](./PRD.md)，模块职责见[系统架构](./ARCHITECTURE.md)，阶段四细节见[阶段四开发指南](./PHASE_04_OPERATIONS.md)，阶段六至十设计见[转型总设计](./superpowers/specs/2026-08-23-ai-knowledge-agent-transformation-design.md)，实施顺序见[开发路线图](./ROADMAP.md)。其他项目文档与本文冲突时，涉及安全边界的行为以本文为准。

## 统一术语

- **授权根目录**：用户通过目录选择界面明确允许应用扫描的真实目录。
- **操作草案**：来自用户或未来 AI 的未信任移动或重命名建议，不能直接执行。
- **已校验计划**：Rust 后端根据操作草案和当前磁盘状态生成的短期、一次性计划。
- **预览**：已校验计划的只读展示，至少包含每项操作的 From/To、类型和校验结果。
- **执行结果**：执行后逐项记录的成功、失败或未执行状态及原因。
- **历史记录**：实际文件操作的持久化审计记录。
- **撤销资格**：根据当前磁盘状态动态判断某条成功记录是否还能安全恢复。
- **临时正文**：用户主动发起内容分析后，由 Rust 在本地提取并仅保存在当前任务内存中的原始文本。
- **AI 分析结果**：经过结构校验的摘要、关键词、建议文件名、已有分类 ID、置信度、理由及其来源与文件身份信息。
- **分类 ID**：用户配置的稳定标识；Rust 将合法标签映射为授权根目录直属的单层目录，AI 不直接决定绝对路径。
- **内容指纹**：内容提取读取文件字节时同步计算、仅用于判断 AI 分析结果是否仍对应当前内容的摘要值；不属于阶段四普通文件操作计划。
- **知识空间**：由用户命名、包含一个或多个明确授权真实根目录的本地项目边界。
- **知识文本块**：用户主动建立知识索引后，从源文件提取并带文档位置、指纹和索引版本的可重建派生文本。
- **上下文范围**：问答或 Agent 允许使用的 `CurrentDocument`、`SelectedDocuments` 或 `KnowledgeSpace` 范围。
- **引用**：Rust 根据本次检索候选和活动索引版本校验后，指向文档位置的证据记录。
- **编辑计划**：Rust 为 Markdown/TXT 保存或版本恢复生成的短期、一次性计划，以 `editPlanId` 标识。
- **Agent 提案**：Agent 白名单写工具产生的草稿、差异或路径预览，不是执行授权。

## 不变量

- AI、React 前端和未校验输入都不能直接执行文件系统写操作。
- 目录扫描和监听不能自动读取正文或调用 AI；内容分析必须由用户明确选择文件并主动发起。
- 临时正文不能写入 SQLite、操作历史、应用日志或扫描目录旁车文件。
- 文件系统始终是真实文件状态的最终事实，SQLite 不能替代执行前磁盘复核。
- 第一版绝不覆盖现有文件或目录。
- 没有有效预览计划和用户确认，不能执行移动或重命名。
- 预览、校验失败、取消和超时不能产生成功执行记录。
- 所有实际执行结果必须与磁盘真实状态一致。
- 阶段六至十实现后，知识空间、索引、问答、编辑和 Agent 同样不能扩大现有文件系统权限。
- 模型输出、文档内指令和 Agent 工具参数始终是不可信输入，不能改变系统规则、工具白名单、上下文范围或审批要求。
- `planId` 和 `editPlanId` 只能由前端在直接响应用户对当前预览的明确确认动作时提交；前端业务逻辑、AI 和 Agent 不得自行确认、访问计划存储或替换预览内容。二者不得进入模型上下文、Agent 工具结果、SQLite 或日志。

## 扫描授权边界

- 应用只能扫描用户明确选择的授权根目录。
- 默认不跟随符号链接、Windows Junction 或其他目录重解析点。
- 索引可以记录链接条目及其基础元数据，但不能自动进入链接目标。
- 用户需要扫描链接目标时，必须单独选择目标的真实目录，使其成为新的授权根目录。
- 扫描器和文件监听器遵守同一边界，不能通过链接扩展到未授权目录。
- 路径归属必须基于规范化路径和平台文件系统语义判断，不能只比较字符串前缀。
- 循环链接、损坏链接和指向授权范围外的链接不得导致递归遍历或扫描失败扩散。

## SQLite 数据边界

- SQLite 数据库统一存放在操作系统为应用提供的应用数据目录中。
- 扫描根目录中不得创建数据库、索引文件、旁车元数据目录或其他应用文件。
- 数据库路径由 Rust 后端通过系统应用数据目录 API 解析；前端不能传入或覆盖数据库路径。
- 文件索引是可重建数据，可以通过重新扫描授权根目录恢复。
- 操作历史不能随索引重建清除。
- AI 分析结果可以持久化，但只能包含摘要、关键词、建议、置信度、理由、Provider/模型标识、分析时间、文件身份、内容指纹和采用状态；不得包含临时正文。
- 阶段七的知识索引是独立、显式授权的数据流。实现后可以持久化带位置的知识文本块与向量，但必须按知识空间隔离、可清除、可重建，并明确展示其数据范围；这不改变阶段五单次 AI 整理分析不得持久化临时正文的规则。
- 重建索引只能清理索引相关数据，不能通过删除整个数据库文件实现。

规划中的对话、引用、文档版本和 Agent 审计也必须位于应用数据目录。对话不保存隐藏推理；Agent 审计不保存完整正文或一次性计划 ID。文档版本快照可保存原始字节以支持恢复，因此必须有独立配额、清除入口和隐私说明。

## 第一版操作范围

- 只支持普通文件的移动和重命名。
- 手动移动的目标目录必须已经存在。
- 阶段五仅允许一个受限目录创建例外：用户接受 AI 分类建议、通过 From/To 预览并确认后，Rust 可在授权根目录直属位置安全创建或复用由合法分类标签派生的单层目录。这不是通用目录操作，AI 不能选择路径，Agent 不能请求任意目录。
- 除上述阶段五单层分类目录例外外，不创建目录；任何目录移动或重命名仍被禁止。
- 不删除文件或目录，也不注册删除 Command、删除执行器或删除界面。
- 跨平台可恢复删除必须作为独立方案重新设计和确认后才能加入。

## 草案、校验、预览与确认

```text
用户输入或 AI 建议
  → 操作草案
  → Rust 全量校验
  → 已校验计划与预览
  → 用户确认 planId
  → Rust 执行前复核
  → 逐项执行
  → 执行结果与历史记录
```

- 前端只能提交结构化操作草案，不能要求后端执行任意路径操作。
- Rust 对整批草案执行全量校验；存在任一无效项时，不生成可确认计划。
- 预览必须与已校验计划来自同一份后端状态。
- 前端确认时只提交 `planId`，不能重新提交或替换源路径、目标路径和操作类型。
- Rust 执行前必须再次复核磁盘状态，不能因为用户看过预览而跳过复核。

## `planId` 生命周期

- `planId` 由 Rust 后端生成，计划只保存在内存，不写入 SQLite。
- 生命周期状态包括：有效、已消费、已取消、已过期；后三者为终态。
- 有效期固定为生成后 10 分钟。
- 执行请求开始后立即消费，不能重复执行。
- 用户取消、超过有效期或应用退出都会使计划失效。
- 无效、已消费、已取消或已过期的 `planId` 必须被拒绝，且不能产生文件变化。

## 执行前文件身份复核

- 校验计划至少记录规范化源路径、规范化目标路径、文件类型、大小和修改时间。
- 平台能够稳定提供文件身份标识时，同时记录并复核该标识。
- 执行前重新读取以上信息；与计划快照不一致时拒绝该项并按批量失败规则停止。
- 第一版的手动普通操作不计算文件内容哈希，避免对大文件产生额外完整读取成本；AI 派生计划按“AI 权限边界”复核内容提取时已有的内容指纹。
- 手动操作不使用内容哈希不降低目标冲突、路径边界或文件类型检查要求。

## 目标冲突与覆盖策略

- 目标路径存在任何文件或目录时即视为冲突。
- 冲突在预览中明确标记，并阻止生成可确认计划。
- 第一版不提供覆盖、替换、自动合并、自动编号或静默改名。
- 用户必须修改目标名称或位置，然后重新提交草案并重新校验。
- 执行前若目标路径新出现，当前项失败并停止后续项目；不得覆盖目标。
- 撤销时目标恢复位置被占用，同样拒绝撤销，不覆盖现有内容。

## 卷边界

- 第一版只支持源文件与目标目录位于同一磁盘或文件系统的移动。
- 跨磁盘或跨文件系统移动在预览校验阶段标记为不支持，并阻止确认。
- 第一版不把跨卷移动降级为复制，也不执行“复制、校验、删除源文件”的替代流程。
- 跨卷能力需要独立定义完整性校验、失败恢复、历史和撤销后才能加入。

## 批量执行与失败

- 确认前必须全量校验所有项目；任一无效项都会阻止整批确认和执行。
- 用户确认后，执行器按已校验顺序逐项执行，并在每项开始前复核磁盘状态。
- 首个运行时失败发生后，立即停止所有尚未开始的后续项目。
- 文件系统批量操作不声明数据库式原子性。
- 不自动回滚已经成功的项目，避免二次失败掩盖真实磁盘状态。
- 每项结果只能是成功、失败或未执行；批次结果由逐项真实状态汇总。
- 失败或未执行项目不能生成虚假的成功记录或撤销记录。
- 已成功项目通过正常撤销流程逐项恢复。

## 历史与撤销资格

- 操作历史默认长期保留，不做自动到期清理。
- 只有实际成功的移动或重命名生成可供撤销判断的历史记录。
- 历史记录存在不代表当前仍然可以撤销。
- 展示历史和执行撤销前都应根据当前磁盘状态重新计算撤销资格。
- 源恢复位置被占用、已移动文件不存在、文件身份不匹配或权限不足时，撤销资格为不可用并给出原因。
- 撤销不能覆盖现有文件或目录。
- 批量操作中已成功项目可以逐项撤销；失败和未执行项目不可撤销。
- 重建文件索引后，历史记录和仍然有效的撤销资格信息必须保留。

## AI 权限边界

- 第一版 AI 不生成删除、通用目录操作、覆盖或跨卷移动建议；它只能返回分类 ID，不能决定单层分类目录的路径或创建时机。
- 第一版内容提取只支持文本型 PDF、TXT、MD、DOCX 和常见代码/配置文本文件；旧版 `.doc`、XLSX、PPTX、OCR 和多模态理解不在范围内。代码文件只按纯文本读取，不执行代码。
- AI 只能返回封闭的严格结构：`summary` 为非空字符串，`keywords` 为非空字符串数组，`suggested_filename` 为不含路径且扩展名与源文件一致的合法文件名，`category_id` 为已有分类 ID 或 `null`，`confidence` 为 `[0, 1]` 范围内的数字，`reason` 为非空字符串。缺少字段、额外字段、类型错误、空必填值或越界值时整项拒绝；通过校验并由用户接受后，结果才能转换为与用户输入相同格式的操作草案。
- AI 不能返回或影响绝对目标路径，也不能请求任意目录。未知分类 ID 被拒绝；无法匹配现有分类时只允许重命名建议。Rust 只可把合法分类标签派生为授权根目录直属的单层目录，并在用户确认后安全创建或复用。
- AI 不能获得 `planId` 的执行权限，不能直接调用执行、历史清理或撤销服务。
- 用户接受 AI 建议后，建议仍须经过 Rust 校验、预览和明确确认。
- 当前 Provider 只允许环回 Ollama，没有远程 Provider 或正文外发入口。
- 临时正文只在内容提取、分段和本地 Provider 调用所需的任务内存中存在，任务完成、失败或取消后释放，不得进入持久化层或日志。
- 内容提取必须在读取字节时同步计算内容指纹，并在提取结束及持久化前复核文件元数据与平台身份；分析期间变化时丢弃结果。持久结果绑定内容指纹，应用重启后加载或转换为操作草案前按需重新计算。AI 派生的草案和已校验计划必须携带该指纹，Rust 执行前再次计算并复核；不一致时结果或计划失效。手动普通操作第一版仍不强制计算内容哈希。
- 扫描 PDF、加密或损坏文档、空文本、格式伪装、解码失败、资源超限、Provider 失败或非法输出均不得产生可执行建议。
- AI 不可用、输出非法或用户拒绝建议时，基础文件管理功能必须继续正常工作。

## 知识空间与知识索引边界（阶段七规划，未实现）

- 一个知识空间只能包含用户通过原生目录选择器明确授权的真实根目录；添加、恢复和切换根目录均须重新核对真实路径。
- 多根目录授权不能通过共同父目录、路径字符串前缀、符号链接、Junction 或监听事件隐式扩大。
- 原文件是事实来源。知识索引不得修改、复制、移动或重命名源文件，也不得在授权根目录写旁车文件。
- 读取前复核授权、普通文件类型、真实格式、文件大小和压缩容器资源；读取中继续执行字符、字节、时间和取消限制。
- 提取时计算内容指纹，并在提取结束、持久化前和活动版本切换前复核文件身份。文件变化时丢弃候选版本。
- 文件变化后，旧活动索引立即停止参与检索；只有单文档的文本块、FTS5 和向量全部成功后才事务切换新版本。
- 文本块和向量按知识空间隔离，并记录提取器、切片、嵌入模型、模型摘要、向量维度和索引版本。
- 向量仓储必须经过接口隔离。任何扩展都要锁定精确版本并在启动时校验版本与维度；失败只能使向量能力降级，不能影响文件浏览或手动操作。
- 默认嵌入模型候选 `qwen3-embedding:0.6b` 当前尚未接入；实现后仍只能接收当前已授权索引任务的文本块。
- 索引任务取消必须释放并发槽位，使排队项进入明确终态，并在应用重启后只恢复可安全重建的工作。

## 检索、问答与引用边界（阶段八规划，未实现）

- 上下文范围只能是 `CurrentDocument`、`SelectedDocuments` 或 `KnowledgeSpace`；默认当前文档，扩大范围必须由用户主动选择。
- Rust 必须验证范围内所有文档属于当前知识空间且活动索引有效，模型不能用文本要求扩大范围。
- 模型只接收本次请求挑选的有限文本块和请求内 `chunkId`，不接收可用于越权访问的绝对路径。
- 每条展示引用必须由 Rust 验证 `chunkId` 来自本次候选且索引版本仍有效。非法引用最多修复一次，仍非法时拒绝展示回答。
- 无候选、低于锁定阈值或证据不足时明确拒答，不能用模型常识伪装成本地证据。
- 对话只保存用户消息、最终回答、范围、模型版本与经校验引用；不得保存隐藏推理或未经校验的 Provider 原始响应。
- 文件变化后，历史引用标为来源已变化，不得继续当作当前有效证据。
- 文档正文中的提示注入是不可信内容，不能修改系统提示、范围、权限或引用规则。本阶段没有写工具。

## Markdown/TXT 编辑边界（阶段九规划，未实现）

```text
用户草稿
  → Rust 基线与权限复核
  → 完整差异 + editPlanId
  → 用户明确确认
  → Rust 消费计划并再次复核
  → 原始版本快照
  → 同目录临时写入与受控替换
  → 编辑历史与索引失效
```

- 只允许当前知识空间授权范围内现有 `.md` 和 `.txt` 普通文件；链接、目录和其他格式只读。
- 不自动保存。关闭标签、切换空间或退出前必须处理未保存草稿。
- `editPlanId` 只在 Rust 内存存在 10 分钟，一次性消费；取消、过期、消费、应用退出后均不可执行。
- 执行请求只提交 `editPlanId`，不能重交路径或正文。前端只能在直接响应用户对当前差异的明确确认动作时提交它；前端业务逻辑、AI 和 Agent 不能自行确认、访问计划存储或替换内容。
- 基线至少绑定规范化路径、类型、大小、修改时间、平台身份和内容指纹；任一外部变化都拒绝覆盖。
- 保存保留原编码、BOM 和换行。快照成功后才写同目录排他临时文件，并使用按平台验证的替换方式；失败不得记录成功。
- 版本恢复也必须生成差异和新的 `editPlanId`，不能覆盖已变化的当前文件。
- 成功编辑立即使旧知识索引失效并触发增量重建；失败不能切换索引版本。

## 受控 Agent 边界（阶段十规划，未实现）

- Agent 在 Rust 中运行，状态只能按 `Queued`、`Running`、`WaitingForApproval`、`Completed`、`Failed`、`Cancelled` 的合法路径迁移。
- 首版工具白名单固定为 `knowledge.search`、`document.read`、`document.propose_create`、`document.propose_patch`、`file.propose_rename`、`file.propose_move`。
- 工具使用封闭 JSON Schema，拒绝未知工具、额外字段、绝对路径、路径穿越、跨空间文档 ID、超量项目和超长结果。
- 只读工具只能访问当前知识空间与当前 `ContextScope`；写工具只能产生 `AgentProposal`，不能写磁盘。
- `document.propose_create` 只生成未保存的 Markdown/TXT 内存草稿；在独立新建文档规范完成前，批准也不能写入磁盘。
- Agent 不依赖文件执行器、计划存储、撤销服务或数据库连接，只调用公开工具接口。
- 模型看不到 `planId`、`editPlanId`、审批凭据或内部路径快照；批准提案后仍由用户进入普通预览与确认流程。
- 单次运行最多 8 个模型步骤、5 分钟；每个知识空间只允许一个活跃 Agent。工具超时和模型重试计入预算。
- 取消贯穿模型请求、工具队列和结果处理；取消、超时或应用重启后不得继续旧步骤、排队工具或旧审批。
- 审计保存模型/提示词版本、工具名、经字段白名单与长度限制处理的脱敏封闭结构化参数、知识空间 ID、相关文档 ID、Rust 权限决策、合法状态迁移和审批事件。不得保存隐藏推理、完整正文、绝对路径或一次性计划 ID。
- 禁止 Shell、删除、覆盖、跨卷移动、任意目录创建、开放网络和桌面控制。

## 禁止暴露的接口

- 任意 Shell 命令执行接口。
- 接受任意命令名的 Tauri 调用包装器。
- 接受未经计划绑定的任意源路径和目标路径执行接口。
- 跳过校验、预览或确认的移动与重命名接口。
- 删除、覆盖、通用目录操作和跨卷移动接口；阶段五受限单层分类目录只能封装在确认后的专用 Rust 执行流程中。
- 接受 AI 提供的绝对路径、未知分类 ID 或目录创建请求并直接转换为操作草案的接口。
- v0.1.0 或本轮知识库路线中的远程 Provider、正文外发入口，或将阶段五临时正文写入 SQLite、历史或日志的接口。
- 由前端指定 SQLite 文件位置或直接执行 SQL 的接口。
- 绕过知识空间和 `ContextScope` 读取文本块、向量、文档或引用的接口。
- 接受模型自报 `chunkId`、路径或索引版本并直接显示为合法引用的接口。
- 接受正文和路径直接保存、绕过差异与 `editPlanId` 的编辑接口。
- 由 AI 或 Agent 确认、消费、查询或持久化 `planId` / `editPlanId` 的接口。
- 动态加载模型提供的工具名，或让 Agent 直接访问执行器、计划存储、撤销服务和数据库的接口。

## 必须覆盖的安全测试

- 未授权路径、字符串前缀伪装路径、符号链接、Junction、循环链接和损坏链接。
- 扫描目录无旁车文件，索引重建保留操作历史。
- 普通文件以外的对象、缺失目标目录和跨卷移动被拒绝。
- 目标在校验时已存在或执行前新出现时均不覆盖。
- `planId` 过期、取消、重复消费和应用会话失效。
- 预览后源文件类型、大小、修改时间或平台文件身份变化。
- 批量预检失败时零执行；运行时失败后后续项目保持未执行。
- 成功、失败、未执行状态与磁盘真实状态一致。
- 历史长期保留，撤销资格随冲突和文件状态变化正确更新。
- AI 输出无法绕过草案、校验、预览、确认和执行权限边界。
- 文本型 PDF、TXT、MD、DOCX 和常见代码/配置文本文件的内容分析结果符合封闭 schema；缺少字段、额外字段、类型错误、空必填值、非法文件名和越界置信度被拒绝，长文档分段汇总不会绕过结果校验。
- 扫描 PDF、加密或损坏文档、空文本、格式伪装、不支持格式、解码失败和资源超限不会调用 Provider 或产生可执行建议。
- 环回地址限制确保阶段五没有正文外发入口；临时正文不会出现在 SQLite、操作历史、应用日志或扫描目录中。
- 有效分类 ID 可由 Rust 映射到授权根直属单层目录并进入完整安全执行链；目录可在确认前不存在。未知分类 ID、绝对路径和任意目录创建输出被拒绝。
- 同大小或相同修改时间的内容替换、分析期间变化、应用重启后加载结果，以及 AI 草案生成后至执行前的变化，都会被内容指纹复核发现并使旧结果或计划失效。
- 多根知识空间隔离、链接/Junction 不扩权、索引源文件零修改、取消释放槽位、崩溃恢复和活动版本事务切换。
- FTS5 与向量范围隔离，文件变化后旧块不参与检索，向量扩展版本或维度错误安全降级。
- 三种 `ContextScope`、跨空间拒绝、非法/跨请求/旧版本引用拦截、一次修复上限和证据不足拒答。
- Markdown/TXT 外部变化、链接替换、编码/BOM/换行、`editPlanId` 生命周期、临时写入失败、版本恢复和 Agent 无法获得计划 ID。
- Agent 状态机、工具 Schema、提示注入、审批、单空间并发、步骤/时间预算、取消/重启终止和审计完整性。

阶段七至十测试与发布门槛见[知识评测规范](./KNOWLEDGE_EVALUATION.md)。这些测试当前尚未运行，不能把本节视为验收通过记录。

## 未来远程 Provider 规范占位（未实现）

远程 Provider 不属于 v0.1.0、阶段六至十或本轮范围。未来若重新立项，必须先设计一次性批次同意凭据，绑定确切文件版本、Provider/模型、发送字段、预计文本量、调用与重试预算及费用范围；任一绑定项变化、取消、消费、超预算或过期均须失效。完成专用接口、零凭据零外发测试和用户可见说明前，不得注册远程适配器。
