# AI File Organizer

AI File Organizer 是一款 Local First 桌面文件整理应用，并正在按已批准设计渐进升级为 IDE 式个人知识库与受控知识工作 Agent。当前可用能力仍是安全扫描、SQLite 元数据索引、浏览搜索、变化监听、经过预览确认的普通文件移动/重命名与本地 AI 内容分析初版；知识工作台、知识索引、RAG、编辑和 Agent 尚未实现。

## 当前状态

| 属性 | 值 |
| --- | --- |
| 状态 | 阶段一至四已完成；阶段五为内部开发版；阶段六至十设计完成、未实现 |
| 当前版本目标 | `v0.1.0` 文件整理基础；`v0.2.0` 知识库与受控 Agent |
| 最后更新 | `2026-08-23` |

仓库已经完成以下基础文件管理能力：

- 使用原生目录选择器授权扫描根目录；
- 只读递归扫描文件、目录和链接元数据，并汇总忽略项与单项错误；
- 将可重建索引保存在系统应用数据目录中的 SQLite 数据库；
- 浏览目录与文件，按名称、路径、类型、大小和修改时间搜索、排序、筛选及分页；
- 监听当前授权目录的新增、修改、重命名和删除事件，并同步索引与界面；
- 重启后恢复最近使用的持久化索引。
- 普通文件移动和重命名经过 Rust 全量校验、From/To 预览、明确确认和执行前复核；目标冲突、目录对象、未授权路径、跨卷移动和覆盖均被拒绝。
- 实际执行结果持久保存到应用数据目录中的 SQLite，支持根据当前磁盘状态逐项撤销。

阶段五已加入本地 Ollama/Qwen2.5 内容分析初版：仅在用户明确选择文件、配置并启用至少一个分类后，读取 TXT、MD、文本型 PDF、DOCX 以及常见编程语言和配置文件正文；生成摘要、关键词、重命名和已有分类建议。当前版本没有远程 Provider 或正文外发入口，不会删除、覆盖或开放通用目录操作。唯一目录创建例外是：用户接受 AI 分类建议、通过 From/To 预览并确认后，Rust 可在授权根目录直属位置安全创建或复用一个由合法分类标签派生的单层目录。

## 开发环境

### 前置条件

- Node.js 24
- pnpm 11
- Rust stable 工具链及 `rustfmt`
- 当前平台所需的 [Tauri 系统依赖](https://v2.tauri.app/start/prerequisites/)

Windows 桌面构建需要 Microsoft C++ Build Tools 和 WebView2。macOS 与 Linux 需要安装 Tauri 文档列出的对应原生依赖。

### 安装

```powershell
pnpm install --frozen-lockfile
```

pnpm 只获准运行 esbuild 必需的安装脚本；该白名单记录在 `pnpm-workspace.yaml`。

### 开发与检查

```powershell
# 浏览器开发服务器
pnpm dev

# Tauri 桌面开发应用
pnpm tauri dev

# 前端类型检查、测试和生产构建
pnpm check

# 分项前端检查
pnpm typecheck
pnpm test
pnpm build

# Rust 检查
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml

# 调试安装包
pnpm tauri build --debug
```

当前应用只注册扫描、索引状态、索引重建、最近索引恢复、搜索和阶段四操作等窄化 Tauri Command，并只授予原生目录选择所需的 Dialog 权限。前端不能直接访问文件系统、SQLite 或 Shell；只有用户选择目录后才会启动只读扫描和授权范围内的变化监听，且文件写入必须经由一次性操作计划。

## 核心原则

- **Local First**：文件保留在本地。当前阶段五的原始正文只在分析任务内存中短暂存在；未来阶段七只有在用户明确建立知识索引后，才会在 SQLite 保存可清除、可重建的派生文本块与向量。
- **AI 只提供建议**：AI 不能直接移动、重命名、删除或撤销文件操作。
- **先预览再确认**：移动和重命名必须经过 Rust 校验，并向用户展示 From/To 预览。
- **不静默覆盖**：目标路径存在任何文件或目录时拒绝执行。
- **操作可追踪**：实际操作写入持久历史，并在当前磁盘状态允许时支持撤销。
- **最小权限**：前端不直接访问文件系统、SQLite 或 Shell，后端不暴露通用文件操作入口。

## v0.1.0 能力与计划

阶段一至四已完成：

- 扫描用户明确选择的本地目录，并建立 SQLite 文件元数据索引；
- 浏览、搜索、排序和筛选索引中的文件与目录；
- 监听授权目录变化，仅更新索引，不自动整理文件。
- 移动和重命名普通文件，批量移动支持全量预检、逐项结果和失败后停止后续项目。
- 长期保存操作历史，并在源路径未被占用、目标文件身份匹配时支持撤销。

阶段五已实现的初版能力：
- 对用户明确选择的文本型 PDF、TXT、MD、DOCX、常见编程语言和配置文件在本地提取正文，根据内容与元数据生成摘要、关键词、智能重命名和分类建议。
- 长文档采用“分段摘要后汇总”；Ollama 以受限 JSON Schema 输出，由 Rust 再次校验。
- AI 只能返回用户配置的已有分类 ID，由 Rust 将分类 ID 映射到现有目录；无法匹配时只建议重命名。接受后的建议进入与手动操作相同的校验、预览、确认和执行流程。

阶段五待完成：
- 修复与验证批次取消的并发槽位、根目录切换/文件变化复核、提取阶段的读取前资源限制，以及建议在预览成功后才标记为采用。
- 使用 80–120 份真实非敏感文档完成黄金集评测并达到发布门槛；未达标时先优化程序约束、提示词和少样本示例。
- 远程 Provider、OCR、XLSX、PPTX、旧版 `.doc`、多模态分析及 QLoRA 训练均不属于首版范围。

第一版不支持删除、覆盖、通用目录操作、跨卷移动、旧版 `.doc`、XLSX、PPTX、OCR 或多模态内容理解；目录能力仅限上述用户确认后的授权根直属单层分类目录。扫描版或图片型 PDF 不会在第一版进行内容分析。代码文件按受限纯文本读取，不执行代码，也不进行语法树或依赖分析。

## v0.2.0 已批准设计（尚未实现）

- 阶段六：将前端重构为左侧多根目录树、中间文档标签页、右侧统一助理面板和底部活动窗口组成的 IDE 式工作台。
- 阶段七：引入项目式知识空间；原文件作为事实来源，SQLite 保存用户明确建立索引后产生的 FTS5 文本块与可替换向量仓储数据。
- 阶段八：支持 `CurrentDocument`、`SelectedDocuments`、`KnowledgeSpace` 三种范围的混合检索与引用问答；Rust 校验所有引用 ID。
- 阶段九：只为 Markdown/TXT 提供手动保存、完整差异、一次性 `editPlanId`、版本快照和外部变化保护。
- 阶段十：在 Rust 中运行受控 Agent；仅允许固定只读/提案工具，所有写入继续由用户审批，且模型永远看不到 `planId` 或 `editPlanId`。

阶段六至十当前均为“设计完成、未实现”。`sqlite-vec` 是可替换向量仓储的首个候选，`qwen3-embedding:0.6b` 是默认嵌入模型候选；二者均尚未接入或评测。跨平台、性能、安全审计与发布顺延为阶段十一。

## AI 内容与隐私边界

- 目录扫描只建立文件元数据索引，不会自动读取或发送正文；内容分析必须由用户明确选择文件后发起。
- 提取出的原始正文不写入 SQLite、操作历史或日志。SQLite 只保存摘要、关键词、建议、置信度、理由、Provider/模型标识、分析时间、文件身份、内容指纹和采用状态。
- 内容提取时同步计算只用于 AI 分析结果的内容指纹；文件在分析后发生变化时，既有结果标记为过期。AI 派生的草案和计划携带该指纹并在执行前复核；手动普通操作仍不强制计算内容哈希。
- AI 不接收文件执行权限，不返回可直接执行的绝对路径，也不能自行创建或选择任意目录。阶段五的单层分类目录只能由 Rust 根据合法分类标签派生，并在用户确认安全操作计划后创建或复用。
