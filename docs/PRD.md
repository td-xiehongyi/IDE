# 个人知识库产品需求

日期：2026-09-06。状态：首版产品方案已确认；实现与验收未完成。决定依据见[启动记录](kickoff.md)，建设顺序见[路线图](ROADMAP.md)。

## 定位与价值

以本地 Markdown 文件夹为基础，提供可日常使用的笔记阅读、编辑和连接体验，配合可参与维护的知识库 Agent。面向用户自己，日常使用优先，兼顾学习和作品展示（D01、D03、D04、D10）。

知识库的价值是让积累的资料能被找到、理解并用于产出。Agent 的通用性来自按任务组合检索、阅读和变更提案工具，不局限于文件关系分析、复习指南或分类整理。相比手动找资料再复制到聊天工具，实际收益须通过真实任务的完成质量、核对成本和修改恢复体验验证；尚未获得商业价值或效率提升的测量证据。

## 首版范围

| 方面 | 已确认需求 |
| --- | --- |
| 平台与规模 | Windows 单机，约几百篇 Markdown；数量是估计，不是性能测试结果 |
| 内容来源 | 本地文件夹为知识库；原始文件为正式内容，允许外部工具修改 |
| 编辑 | 默认即时预览，可切换源码模式；停止输入 1 秒后自动保存；切换/关闭和每 5 分钟保留有变化的历史检查点 |
| 组织 | 新建文件夹、移动/改名单篇笔记、[[笔记链接]]、反向链接、搜索；唯一名称直接定位，同名时选择并保存含目录的链接；改名/移动维护受影响引用。整文件夹操作后续再做 |
| AI | 云端 OpenAI 兼容 API 地址、密钥和模型名；本地 Ollama；系统凭据存储保管密钥 |
| Agent 范围 | 默认当前知识库，可限定文件夹或笔记，不读取其他知识库 |
| Agent 维护 | 新建、修改、重命名、移动和可恢复删除；逐文件查看、整组确认或取消 |
| 恢复 | 历史版本、回收区及任务回退；历史默认长期保留，由用户手动清理；有后续修改或位置冲突时不静默覆盖 |

首版只处理 Markdown 内容，不承诺完整兼容 Obsidian 的插件、主题或全部语法。知识库中的非 Markdown 文件保持原样，不进行内容检索、编辑或 Agent 操作。图片识别、联网搜索、网页读取、其他格式、同步与手机端放到后续；关系图仅为候选，非交付承诺。

数学公式和 Mermaid 图表渲染明确留到后续（D21）。首版保留可编辑公式源码和普通 Mermaid 代码块，模式切换及保存不得破坏其内容；不要求首版完成公式排版或图表生成。

默认一次打开一个知识库，可切换；打开知识库时说明本地索引范围，索引可自动跟随笔记变化更新，但不能自动触发模型调用。品牌名、应用标识和现有数据路径本轮不改。

## 主要流程

### 日常笔记

打开本地文件夹 → 浏览或搜索 → 打开/创建 Markdown → 即时预览编辑或源码编辑 → 自动保存并显示状态 → 链接导航或查看反向链接。用户亲手编辑不需要每次差异审批；恢复历史属于覆盖当前内容的显式操作，应预览并确认。

外部编辑与当前内容冲突时保留双方版本供处理。保存失败必须显示未保存状态并保留编辑内容，不能显示成功。切换笔记或关闭应用时不得悄悄丢弃未保存内容。

### 知识问答

选择模型与可选任务范围 → 输入问题 → Agent 按需搜索/阅读 → 返回答案及可打开的来源。说明哪些是笔记依据、哪些是推断；证据不足时说明缺口，不伪造引用。未检索到不能直接断言整个知识库没有相关信息。

云端发送任务实际需要的内容，不默认一次性上传整个库；本地故障不自动改用云端。网络能力限于用户配置的模型服务，不等于首版具备网页搜索工具。

### 维护知识库

提出任务 → Agent 查阅内容并生成提案 → 查看每篇笔记的差异、路径变化和删除项 → 整组确认或取消 → Rust 复核 → 执行并呈现逐项结果 → 可请求回退。

相关修改一起审批，例如重命名与引用修复。不支持取消其中某项却保留依赖它的修改；用户要求调整时重新生成整组提案。一次确认只覆盖当前展示内容，后续新增变更须再次确认。

删除移入可恢复回收区，不提供 Agent 永久删除。回退范围是该任务实际成功的修改；涉及后续修改、同名占用或文件缺失时暂停冲突项并呈现状态，不承诺一键恢复一定成功。多文件操作不具备数据库事务式原子性。

## 验收

| 给定与操作 | 必须可观察的结果 |
| --- | --- |
| 几百篇实际 Markdown，编辑后重启 | 内容正确保存；即时预览/源码切换及中文输入不破坏正文 |
| 新建链接、重命名和移动笔记 | 链接与反向链接一致；重名/失效目标明确，不随意定位 |
| 外部编辑与自动保存重叠 | 不静默覆盖任意一方；显示冲突或保留可恢复版本 |
| 提出检索、比较或归纳问题 | 原文依据可以打开核对；证据不足明确说明 |
| Agent 提出多文件维护 | 确认前不写文件；取消无变化；执行内容与预览一致 |
| 预览后文件变化 | 原提案不能继续覆盖新内容，要求刷新预览 |
| 执行中断或部分失败 | 显示真实成功/失败/未执行项，能继续处理恢复 |
| 删除、修改后请求恢复 | 正常情况能恢复；冲突时不覆盖后续工作 |
| 清理/重建搜索索引 | 笔记、历史和回收数据不受影响 |
| 分别使用云端和 Ollama | 明确模型能力和错误；不因调用失败假装任务成功 |

测试用隔离副本覆盖失败和恢复，不对用户唯一资料做破坏性验证。性能、检索质量和模型工具调用门槛在相应阶段用真实样本确定，不能用本需求文档替代测试结果。
