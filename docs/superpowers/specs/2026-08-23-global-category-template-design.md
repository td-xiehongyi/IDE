# 全局分类模板与分类配置删除功能

## 目标

全局分类模板作为新检索目录的默认分类方案。模板应用后会复制为当前根目录的本地分类配置，本地修改不会影响模板或其他目录。

分类配置支持安全删除。删除配置只解除分类与当前根目录的关联，不删除实际文件夹、文件、历史记录或已完成操作。

## 配置模型

全局模板保存模板 ID、名称、版本和分类定义。分类定义包含稳定的分类 ID、名称、描述和默认启用状态，不保存本地目录路径。

当前根目录仍使用已有的分类配置保存方式，并额外记录应用过的模板 ID 和版本。应用模板时复制分类定义，并根据安全、语义化的分类标签派生当前根目录下的单层目标目录，例如 `study` 对应 `<当前根目录>/study`。应用模板和保存配置都不会创建文件夹；目录只在用户接受建议、通过操作预览并确认执行后创建或复用。

模板是一次性复制应用，不是实时继承：

- 模板修改不会覆盖已有根目录配置。
- 模板删除不会删除已经应用的根目录配置。
- 根目录配置可以独立新增、修改、启用、禁用和删除分类。

## 安全删除

本地分类列表提供删除按钮和二次确认。后端删除前检查：

- 是否存在待确认的 AI 分析结果引用该分类；
- 是否存在待确认的操作草案将目标指向该分类目录。

存在引用时拒绝删除并返回提示。没有引用时只删除 `ai_categories` 配置记录，物理目录和文件保持不变。

全局模板中的分类支持编辑、新增和删除。删除模板分类只影响以后应用该模板的目录。

## AI 与训练追踪

模板不会直接修改模型权重，也不会自动启动训练。它会统一分析时提供给模型的分类 ID、名称和描述，且不向模型提供本地目录路径。

每个分析结果记录模板 ID、模板版本、标签体系版本和提示词版本，便于后续比较不同分类体系对分类准确率、人工接受率和标签质量的影响。正式训练标签使用 `game`、`study` 等语义化 ID；存在语义化标签时，`category_1`、`category_2` 等占位 ID 不进入新的训练集或黄金集。旧数据中的别名必须在训练集、验证集和黄金集中统一迁移，并重新建立基线。

训练数据只使用用户确认或修正后的结果，不把模型自动建议直接视为真实标签。目录路径、目录创建、文件移动和撤销属于 Rust 应用层行为，不进入模型输入、输出或训练目标。

现有 `qwen2.5:7b` 继续作为基线和回退模型，现有 JSON Schema、阶段四预览确认链、执行时复核、历史记录和撤销机制保持不变。

## 数据库变化

新增：

- `ai_category_templates`
- `ai_category_template_items`
- `ai_root_category_templates`

`ai_analysis_results` 增加可空的 `template_id` 和 `template_version` 字段，以兼容未使用模板的旧配置和历史结果。

模板表和分析元数据由数据库版本 4 引入；版本 5 进一步把本地分类目录映射规范化为根目录下由分类标签派生的目录。迁移只更新配置记录，不创建、移动、重命名或删除物理文件。

## 接口与界面

后端新增模板查询、保存、删除、应用接口，以及当前根目录分类删除接口。应用模板接口会重新执行根目录授权、分类标签安全性、单层目录边界和大小写不敏感唯一性校验；目标目录已存在时还必须确认它是授权根目录内的普通目录，目标目录不存在时允许保存配置但不立即创建。

前端在“配置分类”面板中提供：

- 全局模板选择、创建、编辑、保存、应用和删除；
- 模板分类新增、编辑和删除；
- 本地分类配置删除；
- 模板应用后展示由分类标签派生的目标目录，并允许本地配置独立修改，不要求逐项绑定预先存在的文件夹。
