## 第一阶段：可日常使用的 Markdown 知识库

目标：用户可以在本应用管理几百篇笔记，不依赖 AI 完成日常阅读编辑。

真实文件与保存流程的设计草案已形成，见[第一阶段设计](FIRST_STAGE_DESIGN.md)和[分步实施计划](superpowers/plans/2026-09-06-phase-01-real-files-and-saving.md)。当前停在设计评审，未开始安装编辑器依赖或修改功能代码。

依赖：先核对现有未提交实现和数据库迁移，完成编辑器与存储方案设计。交付打开/切换目录、即时预览与源码模式、自动保存状态、搜索、链接与反向链接、笔记新建/改名/移动、历史版本和回收恢复。

近期设计任务：
- 用真实 Markdown 样本验证编辑器：中文输入、代码块、列表、表格、源码往返和长笔记；需要时先出独立 UI 预览。
- 明确链接解析与重名、断链、标题和路径规则，定义改名/移动后的引用更新及冲突行为。
- 定义自动保存节奏、版本与恢复数据位置、配额、清理入口、跨卷回收协议及中断恢复；保护现有数据库和旧操作历史。
- 定义失败、未保存、外部修改、关闭/切库和恢复冲突的交互，再锁定依赖与接口。

验收：真实规模笔记可读写，重启不丢内容；中文输入与源码切换正确；引用一致；外部修改不被覆盖；回收与恢复在正常和中断路径上可信；索引重建不影响历史。记录目标机器与样本规模后确定性能门槛。

停止点：本阶段实现须另外明确授权；自动检查和真实 Windows 桌面验收分别报告。通过后也不自行开启下一阶段。

## 第二阶段：知识检索与 AI 回答

目标：对当前库或指定范围提出问题，获得可核对的笔记依据。

依赖：可靠文档读取、范围、索引版本与基础搜索。交付云端 OpenAI 兼容连接、Ollama、系统凭据存储、任务范围选择、检索/阅读、引用定位、取消和明确错误。

验证中文标题/正文、同义问题和找不到依据的情况。先不引入独立向量服务；若关键词检索不能满足实际问题，再比较嵌入检索收益和成本，不沿用旧模型候选为必装项。逐一验证目标 Provider 的工具调用与结构输出能力。

验收：真实检索、比较、归纳问题可追溯；错误与无依据如实表达；不超范围；本地与云端分别走通，密钥不泄漏。锁定样本及期望依据后确定召回与引用门槛。

停止点：完成阶段验收，不把只读问答当成最终首版交付。

## 第三阶段：Agent 维护与任务回退

目标：Agent 自行组合库内工具完成任务，维护操作可审查、可执行、可恢复。

依赖：前两阶段和已验证的历史/回收基础。交付受限多步循环、列目录/搜索/读笔记/变更提案工具、任务预算与取消、逐文件差异与整组确认、执行前复核、逐项结果、任务回退与冲突处理。

验收：使用隔离笔记副本完成新建指南、更新多篇内容、改名并修复引用、移动、回收与恢复；确认前零写入，重复/失效审批被拒绝；外部编辑、取消、中断和部分失败不丢失真实状态；注入内容不能扩大权限。

停止点：完成真实 Windows 完整流程与用户日常试用后评估首版可用性。安装包和发布另行验收，不凭文档或构建成功宣称可发布。
